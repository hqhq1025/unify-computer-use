## [2026-07-29 13:19] | Task: 修复 Linux runtime 在 libatspi < 2.52 上全线失败

### 🤖 Execution Context
* **Agent ID**: `claude-code`
* **Base Model**: `Claude Opus 5`
* **Runtime**: `Claude Code / Linux x86_64 容器（Ubuntu 22.04 + Xvfb X11 + XFCE + at-spi2-core 2.44）`

### 📥 User Query
> 在 Ubuntu 22.04 上，`get_app_state` 全部失败并报 `'Accessible' object has no attribute 'is_text'`，Linux runtime 完全不可用。

### 🛠 Changes Overview
**Scope:** `apps/OpenComputerUseLinux` 的 AT-SPI 接口探测（`runtime.py`）。

**Key Actions:**
- **可移植的接口判定**: 新增 `has_text_iface()` / `has_editable_text_iface()`，改用 `get_text_iface()` / `get_editable_text_iface()` 是否为 `None` 判断，替换 4 处对 `Accessible.is_text` / `is_editable_text` 的属性访问（位于 `text_value`、focused-text 读取、`find_editable_text`、`set_element_value`）。

### 🧠 Design Intent (Why)
*`Accessible.is_text` / `is_editable_text` 是 libatspi 2.52+ 才加入的便捷属性。Ubuntu 22.04 携带的是 at-spi2-core 2.44，这些属性不存在，任何遍历到文本节点的调用都会抛 `AttributeError`，导致 `get_app_state` 整体失败、Linux runtime 在该发行版上完全不可用。*

*现有的 `safe()` 包装器兜不住这种情况：它接收的是 callable，而 `node.is_text` 是**属性访问**——在传进 `safe()` 之前求值就已经抛出异常了。改用 `get_text_iface()` / `get_editable_text_iface()` 是更基础的判据，新旧版本都存在，无需引入版本判断分支。*
